# 控制面板换肤（Theme）设计

> 适用范围：[`web/panel-dot.html`](../../modules/10-smart-control/gateway/esphome/web/panel-dot.html) —— ESP32 自托管的手机控制面板。
> 目标：**换一套皮肤 = 只改 CSS 变量，不改任何组件规则、不碰数据层。**

---

## 1. 为什么这么设计

面板是一个 **单文件、gzip 后打进 Flash、完全离线** 的页面。这带来三个硬约束：

| 约束 | 影响 |
|---|---|
| 单文件进 Flash | 不能引入外部主题 CSS/JS，皮肤必须写在同一文件里 |
| gzip 后体积有限 | 皮肤必须是"纯变量覆盖"，不能复制整套组件样式 |
| 离线 | 不能用 CDN 字体，字体必须内嵌（见 §5） |

所以方案是**单层 CSS 自定义属性契约**：组件样式只写一次、只消费 token；每款皮肤只是一组 `--token: value` 覆盖。

---

## 2. Token 契约

全部 token 定义在 `<style>` 顶部的 `:root`，按 8 类分组。**组件规则里不允许出现写死的颜色/圆角/字体**。

### 2.1 字体族

| Token | 说明 |
|---|---|
| `--font-body` | 正文、按钮、格子标签 |
| `--font-num` | 数值、大写字、时钟 |
| `--font-num-weight` / `--font-num-spacing` | 数值字重与字距（像素字只有 400/700，系统字可细调） |

> **像素数字不适合所有风格。** `paper` 用像素数字（点阵是它的主题）；
> `night`/`neon` 用系统等宽（深底上像素字会发毛），`contrast` 用系统无衬线粗体（笔画最实），
> `sand` 用系统无衬线中黑（车漆调性偏柔）。换皮肤时数值字体会跟着换，不只是换色。
| `--font-mono` | 仅日志区（时间戳/十六进制需要等宽对齐） |
| `--cjk-sys` | 系统中文栈（苹方 → 鸿蒙 → 思源 → 雅黑） |
| `--cjk` | **当前皮肤实际用的中文族**，默认等于 `--cjk-sys`；`paper` 覆盖成 `'PxCJK', var(--cjk-sys)` |

### 2.2 表面与文字（按层级由底到顶）

| Token | 用在哪 | paper 默认 |
|---|---|---|
| `--c-page-bg` | 手机壳之外的页面底色 | `#EDEDEB` |
| `--c-shell` | 顶栏 / 底栏 | `#FAFAF8` |
| `--c-card` | 卡片 | `#FFFFFF` |
| `--c-sunken` | 卡片内的凹槽块（`.stat` / 单体格 / 皮肤按钮） | `#EDEDEB` |
| `--c-raised` | 选中态块 / 进度槽 | `#E4E4E1` |
| `--c-text` | 主文字、图标 | `#2B2B2B` |
| `--c-text-2` | 次级文字、压在页面底色上的提示 | `#4A4A48` |
| `--c-text-3` | 弱化文字 / 提示（只在有卡片底处用） | `#61615D` |
| `--c-line` | 卡片描边、分隔线 | `#D7D7D3` |
| `--c-line-2` | 更重的描边 | `#C4C4BF` |
| `--surf-alpha` | 表面不透明度：卡片 / 格子 / 情景卡 | `62%` |
| `--surf-alpha-2` | 嵌套凹槽的不透明度（`.stat` / `.skin-btn`） | `48%` |

> `--c-text-2` / `--c-text-3` 不是"随手调的灰"。它们要压在**会动的光斑**上，
> 所以是按光斑最坏底色反解出来的，不是按平底。见 §5.2。

### 2.3 语义色

**语义不随皮肤改变**：`ok` 永远是"正常"，`danger` 永远是"异常"。皮肤只换色相，不换含义。

| Token | 含义 | paper 默认 |
|---|---|---|
| `--c-accent` | 主强调：激活 / 选中 / 导航下划线 | `#C4262E` |
| `--c-info` | 信息：联网、焦点环 | `#2C6E8F` |
| `--c-ok` | 正常 / 充电中 / 电量充足 | `#2F7A4D` |
| `--c-warn` | 警告 / 压差偏高 / 电量偏低 | `#A8730F` |
| `--c-danger` | 异常 / 告警 / 电量告急 | `#C4262E` |
| `--c-ok-bg` `--c-warn-bg` `--c-danger-bg` | badge 浅底，用 `color-mix` 自动派生 | — |

> 电量环的三档配色由 JS 读 `--c-ok / --c-warn / --c-danger`，改皮肤这圈颜色自动跟着变。

### 2.4 控件

| Token | 说明 |
|---|---|
| `--c-switch-off` / `--c-switch-on` / `--c-knob` | 开关轨道与旋钮 |
| `--c-slider` | 滑块强调色 |
| `--c-mark-on` | 开关格下方小圆点（开启态） |
| `--c-scene-on` | 情景卡激活描边 |

### 2.5 形状

| Token | 说明 |
|---|---|
| `--r-card` / `--r-block` / `--r-chip` / `--r-pill` | 圆角四档 |
| `--bd-card` / `--bd-card-on` | 卡片描边（可改成 2px 做高对比） |
| `--shadow-card` / `--shadow-knob` | 阴影 |
| `--glow-accent` / `--glow-text` | **激活态柔光**。取自 `design/cabin-climate.html` 的 `0 0 22px -10px`（负扩散，可见光晕仅约 12px） |
| `--glow-tile` | 密集网格（开关格）专用、更收敛的柔光。格子间隔只有 8px，照搬 22px 会串色 |

> **视觉基准**：排版与装饰细节以 [`design/cabin-climate.html`](cabin-climate.html) 为准 ——
> 卡片内边距 `16px 16px 18px`（`--pad-card`）、激活柔光、图标描边 1.4、
> 区块标题 17px/500 的字重与间距、雪花等图标用「6 主轴 + 12 斜枝」的精细版本。
>
> **激活态的正确做法**（照设计稿）：**底色不换**，只让描边变强调色 + 图标变强调色 +
> 描边外侧一抹负扩散柔光。不要用灰色底填充整块——那是错的视觉重心。
> 设计稿里只有 `.mode.heating.on` 用了一层极淡的 `linear-gradient(180deg, rgba(43,43,43,.05), transparent 70%)`。

### 2.6 排版

`--fs-sec` `--fs-label` `--fs-body` `--fs-val` `--fs-num` `--fs-clock` `--fs-nav` `--fs-log` `--lh-tight` `--lh-body`

字号阶梯（刻意拉开，避免"什么都差不多大"的死板感）：

| 层级 | token | 默认 | 用在哪 |
|---|---|---|---|
| L1 显示 | `--fs-num` | 24px | 环形仪表中间数字 |
| L2 标题/数值 | `--fs-sec` / `--fs-val` / `--fs-clock` | 15–16px | 区块标题、stat 数值、时钟 |
| L3 正文 | `--fs-body` | 13px | 格子标签、正文 |
| L4 辅助 | `--fs-label` / `--fs-nav` / `--fs-log` | 10.5–11px | 小标签、导航、日志 |

**图标与文字的比例**：`--icon-size` 默认 22px 配 13px 文字（约 1.7 倍）。
早先做过 26px 对 12px（2.2 倍），图标压过文字、正文像陪衬，所以收回来了。

间距：`--pad-card`（卡片内边距）、`--pad-block`（卡片内小块）、`--gap-card`（卡片间距）。

### 2.7 图标

| Token | 说明 |
|---|---|
| `--icon-size` / `--icon-nav` | 图标尺寸 |
| `--icon-stroke` | **SVG 描边宽度**（JS 在切皮肤时写回每个 `<svg>`）。默认 1.5，高对比皮肤 2.1 |
| `--icon-off-opacity` | 关闭态图标透明度 |

### 2.8 装饰

| Token | 说明 |
|---|---|
| `--bg-texture` / `--bg-texture-size` | **页面底纹**。可叠 gradient/网点/网格，默认 `none`。让皮肤有气质，避免全是平涂大色块 |
| `--deco-dotword-opacity` | 点阵大字透明度 |
| `--deco-focus` | 键盘焦点环 |
| `--deco-sec-bar` | 区块标题左侧竖条 |

## 3. 内置皮肤

| id | 名称 | 定位 |
|---|---|---|
| `paper` | Paper | **默认**。暖白 + 不规则纸浆斑 + **中文也是点阵** + 红点缀 |
| `night` | Night | **安静的夜色**：无网格、无外扩辉光、大圆角、柔和系统数字 |
| `neon` | Neon | **通电的 HUD**：青电网格 + 扫描线 + 激活格呼吸光 + 等宽拉开字距 |
| `contrast` | Contrast | 纯黑白 + 2px 描边 + 粗图标，户外强光可读，无任何动效 |

每套皮肤都需同时满足：文字对比度过 AA、4 套皮肤 × 4 个页面 × 4 种屏幕无溢出、
无 JS 报错。

> **`night` 与 `neon` 曾经看着差不多**（都是"深色 + 顶部光"），因为区别只在底纹疏密。
> 现在按**概念**分开：`night` 是"关掉装饰的深色"——纯色、大圆角、无外扩光、系统无衬线数字；
> `neon` 是"仪表盘 HUD"——小圆角、描边发光、等宽数字拉字距、底纹会动。
> 教训：两套皮肤只有在**构成语言**上不同才算不同，只调色值不解决问题。

> **深色皮肤的卡片底色是刻意提亮的**（`night` `#262C35`、`neon` `#1A2533`，
> 比"纯黑系深色"惯用的 `#1A1D20` 亮一档）。原因不是审美：
> 光斑会把页面提亮，卡片半透明后必须**始终比页面亮**，否则在光斑最强处
> 卡片看起来比背景还暗——层次反转，像破图。留出的这点亮度就是余量。

### 已删除的皮肤（不要再加回来）

| 曾经的 id | 删除原因 |
|---|---|
| `terminal` | 满屏绿字太刺眼，实际使用场景没有 |
| `sand` | 淡黄底 + 白卡片与 `paper` 视觉上太接近，定位重复 |

删皮肤时**必须**同步更新 `SKIN_OK` 白名单（`<script>` 顶部防闪白脚本里的对象字面量）。
否则老用户 `localStorage['forager_skin']` 里存着已删除的 id 时，会贴上一个没有任何规则的
`data-skin`，页面退化成"只有 `:root` 默认值、且中文不是点阵"的破图状态。

### 各皮肤底纹与数值字体

| 皮肤 | 底纹 | 底纹动效 | 数值字体 | 中文 |
|---|---|---|---|---|
| paper | SVG 噪声颗粒（180px 无缝，压暗约 4 级） | 44s 斜向漂移 | 像素 Silkscreen | **点阵 PxCJK** |
| night | 极淡顶部冷光 | 12s 呼吸 | 系统无衬线 600 | 系统 |
| neon | 青电网格 30px + 顶部电光 | 13s 网格漂移 + 6s 扫描线 | 系统等宽 500 + 1px 字距 | 系统 |
| contrast | **无**（对比度优先，纹理是干扰） | **无** | 系统无衬线 700 | 系统 |

切换方式：设置页 →「外观 / 皮肤」，选择存 `localStorage['forager_skin']`。

### 设计教训：浅色皮肤别把明度做平

> `sand` 皮肤本身已删除（与 `paper` 定位重复），但这条教训对任何浅色皮肤都成立。

`sand` 初版 page 与 card 都是米黄（`#EAE0D2` → `#FBF6EC`），明度差只有约 8%，
整屏糊成一片、看着发闷。修正版把**卡片拉成纯白 `#FFFFFF`**，页面才保留淡黄，
层次立刻出来。同理，强调色要在白底上够深（`#B07C1A` 而非 `#B4562A`）才够读。

## 4. 新增一款皮肤

**只需 4 步，不用改组件规则：**

1. 在 `<style>` 的皮肤区加一段覆盖：

```css
[data-skin="ocean"]{
  --c-page-bg:#0A1620; --c-shell:#0E1E2A; --c-card:#12293A;
  --c-sunken:#173245;  --c-raised:#1D3D53;
  --c-text:#DCEEF7;    --c-text-2:#8FB3C7; --c-text-3:#5F8199;
  --c-line:#1E4055;    --c-line-2:#2A5A75;
  --c-accent:#4FC3F7;  --c-info:#4FC3F7;
  --c-ok:#5FD08A; --c-warn:#F0B94B; --c-danger:#FF6B6B;
  --c-switch-off:#22455C; --c-switch-on:#4FC3F7; --c-knob:#DCEEF7;
  --c-slider:#4FC3F7; --c-mark-on:#4FC3F7; --c-scene-on:#DCEEF7;
  --deco-sec-bar:var(--c-text-2);
  --deco-focus:var(--c-info);
}
```

2. 在 JS 的 `SKINS` 注册表加一行（`id` 必须与 CSS 选择器一致）：

```js
{ id:'ocean', name:'Ocean', note:'深海蓝' },
```

3. 在 `SKIN_SWATCH` 加缩略图配色（底 / 卡片 / 强调）：

```js
ocean: ['#0A1620','#12293A','#4FC3F7'],
```

> 只覆盖**真正需要变**的 token，其余自动继承 `:root` 默认值。

## 5. 字体

像素字体无法从 CDN 加载（离线），因此以 `@font-face` + `data:font/woff2;base64` 内嵌：

| 字体 | 用途 | 大小 |
|---|---|---|
| Pixelify Sans | 拉丁正文 `--font-body` | 7.6 KB |
| Silkscreen 400/700 | 数值 `--font-num` | 3.5 + 3.2 KB |
| **Fusion Pixel 12px** | **中文点阵 `PxCJK`**（仅 `paper`） | **17.6 KB** |

**如果要换字体**：替换对应 `@font-face` 的 base64，或让某款皮肤改 `--font-body` 指向另一族。


### 5.1 点阵中文（PxCJK）

`paper` 皮肤的中文也是点阵——这是它气质的核心，之前只有数字/字母是点阵、中文是苹方，
所以"点阵"只成立了一半。

**来源**：[Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font) 12px 比例宽度 SC，
SIL OFL-1.1（可商用、可嵌入，需保留版权声明——已写在 `@font-face` 上方注释里）。
装包：`@fontsource/fusion-pixel-12px-proportional-sc`（npm）。

**为什么要子集化**：全量 SC 字体 602 KB，直接内嵌会让页面从 44 KB 涨到 600 KB+。
本页面需要的中文字符是**有限且固定**的（界面文案全部写在 HTML/JS 里），
按实际用字裁剪后只剩 **17.6 KB**。代价是页面 gzip 从 44.2 KB 涨到 62.7 KB。

**⚠ 维护陷阱：改了中文文案就要重建子集。**
新出现的字不在子集里，会静默回落到系统字体——同一个标签里出现两种中文字体。
重建流程：

```bash
# 1. 取字体（只需一次）
npm pack @fontsource/fusion-pixel-12px-proportional-sc --cache /tmp/npmcache
tar xzf fontsource-fusion-pixel-12px-proportional-sc-*.tgz

# 2. 抽出页面上实际用到的非 ASCII 字符
python3 - <<'EOF'
import re, pathlib
s = pathlib.Path('panel-dot.html').read_text()
body = s[s.index('</style>'):]                    # 跳过 CSS 里的 base64
body = re.sub(r'base64,[A-Za-z0-9+/=]+', '', body)
chars = {c for c in body if ord(c) > 127}
pathlib.Path('/tmp/chars.txt').write_text(''.join(sorted(chars)))
print(len(chars), '个字符')
EOF

# 3. 子集化（--layout-features='' 去掉用不到的 OpenType 特性，能省一成体积）
pyftsubset package/files/fusion-pixel-12px-proportional-sc-latin-400-normal.woff2 \
  --text-file=/tmp/chars.txt --flavor=woff2 --layout-features='' --no-hinting \
  --output-file=/tmp/sub.woff2

# 4. base64 后替换 panel-dot.html 里 PxCJK 的 @font-face src
base64 -i /tmp/sub.woff2 | tr -d '\n'
```

**字号必须对齐 12px**：点阵字形按 12px 像素网格设计，在 13px 处会轻微发虚。
所以 `paper` 皮肤把 `--fs-body` / `--fs-sm` 覆盖成 `12px`；其它字号（标题 15 / 微型 10）
仍会缩放，视觉上可接受，但如果要极致锐利，就得再嵌一套 Fusion Pixel 10px（约 +12 KB），
当前判断不值得。

**不设 `unicode-range`**：子集里本来就没有 ASCII 字形，靠字体栈顺序
（`--font-body: 'PxBody', var(--cjk), sans-serif`）就能让数字/字母走 Pixelify、
中文与 `·—…→` 这些符号走 PxCJK，缺字形（如 `⚠`）自动回落系统字体。
若硬写 `unicode-range` 反而会把 `·—…→` 排除掉。

### 5.2 动效与 3D 层次

目标：背景"在动"，而且有**纵深**（3D 感），深色皮肤也要。

#### 为什么第一版"动不起来"

第一版只做了**图案自身漂移**（网点 56s 内移动 14px），实测 **0.25 px/s**——
人眼要看出位移，背景元素至少得有 **2 px/s** 量级的移动。所以那一版等于没动。

结论：**图案漂移再快也看不见**，因为位移尺度只有十几像素。
真正的可见动感来自**几百像素级的大面积光斑缓慢横移**。

#### 背景的最终形态：点阵云（静态点阵 + 双层柔光，横向动效全部删除）

背景动效一共试了四代，每代都被实测反馈否掉，最后收敛到"基本静止"：

| 代 | 做法 | 实测反馈 |
|---|---|---|
| 1 | 三团彩色光斑平移 | 「很多色块」 |
| 2 | 云（多层径向渐变 + 位移） | 「像瓷砖铺贴」、边界没处理好 |
| 3 | 两层半调网点 + 大幅平移 | 「太闪了」（细网点滑动 = 摩尔纹爬行） |
| 3b | 两层半调网点 + 只呼吸 | 「从左到右的效果，有点奇怪」 |
| 4 | 静止纹理（纸纹 / 网格）+ 纵向扫描 | 「是停止了，我还是需要背景动起来」 |
| 5 | 静止纹理 + 一条纵向**软光带**（10% 墨、40vh 高、24s 往复） | 「还是没效果」 |
| 6 | 纵向扫描带（13% 墨、14vh 高、9s 扫一遍、双带错相） | 「有效果，但我不喜欢，还不如最前面的点阵云」 |
| 7 | **点阵云**：静态点阵底纹 + 双层柔光纵向慢漂（视差） | 当前版本 |

##### ⚠ 陷阱一：背景层禁止横向平移（"从左到右"的真正来源）

第 3b 代已经没有任何大幅位移了，用户仍报「有个从左到右的效果，好像是手机才有的」。
原因是背景里所有层都还在**水平方向**漂：纸纹 `dotDrift` +180px、霓虹网格
`gridDrift` +60px、网点层 `halDrift` ±3%。这些是超大定图层（比视口大 12–75%），
Safari 的合成器会把它们按条带重绘，于是横向位移被读成**一道从左往右推进的亮/暗带**。

**规则：背景层只允许 `opacity` 与纵轴（`translateY`）动画，永不改 X。**
现在纸色皮肤的 `.bg-fx` 是 `--bg-fx-name:none`（完全静止），
只有发光类皮肤的扫描线保留纵向 `scanSweep`。

##### 陷阱二：深色皮肤用"线条"，不用网点

用户对深色背景的原话是「深色背景不是这个，就那个线条就可以了」。
所以：`neon` 只保留 30px 网格线（+ 纵向扫描），`night` 只保留顶部冷色渐变
与极慢的 `breathe`（纯 opacity，无位移），`paper` 是纸纹颗粒。
**不要再往深色皮肤上叠网点/光斑**。

##### 陷阱三：底纹只能是"不可识别的细颗粒"

底纹试过的三种写法都不能用：

| 写法 | 结果 | 反馈 |
|---|---|---|
| 规则网点 0.9px / 14px / 7% | 远看只是灰雾 | 「太细了」 |
| 规则网点 1.6px / 22px / 13% | 满屏密集小孔 | 「密集恐惧症」 |
| 不规则大斑纹 + 默认 repeat | 每 300px 一模一样重复 | 「像瓷砖铺贴」 |

规律：**只要图案"可被识别"，就必然失败**——要么太弱看不见，要么强了变成密集小孔/壁纸。
现在的实现是 SVG `feTurbulence` 噪声（`stitchTiles="stitch"`，墨色 alpha≈.037，180px 贴片），
像素上每 180px 确实重复，但没有可识别特征，眼睛不会读成图案。

> 这个坑用**对比度**测不出来（只有 5–7%，看着很淡），必须测**空间频率**：
> 模糊 2px 后 ≤3 级、模糊 12px 后 ≤1 级。修前 7 / 5（明显块状），修后 2 / 0。
> 详见"纸纹的验收判据"。

##### 现行方案：点阵云（`.bg-fx` + `.bg-fx::before` + `.bg-fx .l-near`）

第 6 代的扫描带"有效果"——用户确认看得见了——但回复是「我不喜欢，还不如最前面的
**点阵云**」。这是最重要的一条产品判断：**动效首先得是用户认得的那个意象**，
其次才是强度。扫描带是"扫描仪"，点阵云是"纸面上的云"，后者才是这套设计的语言。

点阵云 = **静态点阵底纹** + **底下两层缓慢漂移的柔光**：

```css
/* 底纹：静态点阵，14px 网屏、7% 墨、0.9px 点 → 提供"点阵"的语言 */
--bg-texture:radial-gradient(circle at 1px 1px,
  color-mix(in srgb,var(--c-text) 7%,transparent) .9px, transparent 0);
--bg-texture-size:14px 14px;
--bg-fx-name:dotDrift; --bg-fx-dur:26s;   /* 点阵以 1.6px/s 极慢上移 */

/* 柔光：远层 inset:-25%，慢、位移小；近层 inset:-45%，快、位移大 → 视差 */
.bg-fx::before{ animation:glowPan 12s ease-in-out infinite alternate; }
.bg-fx .l-near{ animation:glowPanNear 8s ease-in-out infinite alternate; }
@keyframes glowPan{
  from{transform:translate3d(0,-28%,0) scale(1)}
  to{transform:translate3d(0,28%,0) scale(1.26)}
}
@keyframes glowPanNear{
  from{transform:translate3d(0,30%,0) scale(1.1)}
  to{transform:translate3d(0,-30%,0) scale(1)}
}
```

**关键改动：把所有位移改成纵向。** 最早的版本是横向漂移（±18% X），真机上会被
Safari 的条带合成读成"一道从左到右的亮带"。点阵云的**意象**不需要横向移动——
纵向漂移 + scale 一样有视差，而且安全。

各皮肤墨量（对比度余量决定上限，都实测过 AA）：

| 皮肤 | 底纹 | 柔光墨量（远/近） |
|---|---|---|
| paper | 14px 点阵 7% | accent 12% + warn 12% / accent 8% |
| night | 顶部冷色渐隐 9% | #2A7488 16% + #5C4F8C 13% / #2A7488 12% |
| neon | 顶部 14%（静态）+ 30px 网格线单独一层、13% 墨、5px/s 上移 | 单层 #12889B 6%（只为厚度） |
| contrast | 无 | 无（整层 `display:none`） |

⚠ 深色皮肤的柔光要**靠提速而不只是加墨**：墨量加到 20% 以上，夜色会变成"彩色雾"，
那就又回到"很多色块"的老问题。night 最终是 16% 墨 + 10s 周期。

##### 深色皮肤：不要"扫描"

用户对深色的明确要求是「不要这个扫描的效果」。neon 原来有一条 6s 扫过全屏的亮线
（`scanSweep`），已整条删除，`@keyframes` 也一并移除。深色现在的动感来自：

- **网格线整体上移**：网格线单独成层（`--bg-fx2` + `--bg-fx2-size`），
  上移一个完整周期（30px / 6s = 5px/s）后无缝回到起点 —— 线条在动，
  但没有亮线扫过全屏。网格必须单独成层：底色里的顶部渐隐不是周期性的，
  跟网格一起漂移会在循环处跳一下。
  线条墨量 13%、neon 卡片透明度提到 50%：卡片会盖住 85% 面积，
  线条只在缝隙里露 6% 像素是看不出来的，必须让它能透过卡片。
  实测缝隙内帧差 1.53、>8 级像素 8.2%（该看得见的标准）。

> 本次只改 neon（用户指定）：night 保持"安静夜色 + 柔光"不变。
- **一层极低墨量柔光**（6%）做厚度，远低于线条本身的存在感。

> 深色背景的"层次"应该来自**线条与明暗**，不是来自"光扫过"。
> 扫描类动效（扫描线、扫描带）在深色上一律不要。

##### 两套动效要用两种指标验收

| 动效类型 | 该看的指标 | 判据 |
|---|---|---|
| 有硬边的（扫描带、扫描线） | 逐像素帧差 | 平均差 ≥1.5、>8 级像素 ≥5% |
| 平滑的（点阵云、柔光） | 区域均值摆动 | 可见缝隙/页面上 ≥5 级 |

点阵云实测：区域均值摆动 paper 2.4–15.8 级（左右缝隙 15.8/11.5）、night 1.9–5.7、
neon 3.4–10.7；逐像素帧差只有 paper 1.12 / neon 0.85 / night 0.79 ——
这不是"动得不够"，而是平滑动效本来就该用区域亮度看，用帧差会低估它。

##### 那"动感"还剩什么

背景光带负责"一直有点东西在动"，内容侧负责"操作有反应"：页面切换（`pageIn`）、
顶栏进度条过渡（`.sb-fill` 的 width .4s）。背景再往回收（横向、图案、网点）
都会退回前面四代的坑里，不要再试。

#### 半透明表面：光要能透上来

只让光在卡片缝隙里流动是不够的（缝隙只占屏幕约 18%）。用两个 token 控制：

| Token | 含义 | paper | night | neon | contrast |
|---|---|---|---|---|---|
| `--surf-alpha` | 卡片 / 格子 / 情景卡 | 62% | 55% | 55% | 100% |
| `--surf-alpha-2` | 嵌套凹槽（`.stat` / `.skin-btn`） | 48% | 45% | 45% | 100% |

```css
.card, .tile, .scene-btn{
  background:color-mix(in srgb,var(--c-card) var(--surf-alpha),transparent);
}
```

> **关键前提：只有一层**。`.tile` / `.scene-btn` / `.card` 都是**直接贴在页面背景上**的
> （格子不在卡片里）。所以透明度不会被叠乘吃掉。
> 如果哪天把格子挪进卡片里，`(1−0.62)² = 0.14` 的透光率会让效果几乎归零。

`--surf-alpha-2` 是给**压在卡片之上**的凹槽块用的。不做的话，能源卡里 6 个
`.stat` 会把整张卡盖死，实测卡片区域在动画周期内平均亮度只变 **0.2 级**。

#### ⚠ 陷阱四：深色皮肤不能靠"提亮"制造动感

光斑提亮页面 → 页面亮度逼近卡片亮度 → 半透明后**层次反转**（卡片比背景暗）。
`neon` 初版实测层次差 **−13.3 级**，也就是卡片在光斑处直接比背景还暗。

深色皮肤改用**亮度相近、色相不同**的两团光（青 ↔ 紫 / 青 ↔ 品红）：
色相漂移肉眼很敏感，而总亮度仍在预算内，卡片始终比页面亮。

```css
/* night */
--bg-glow:
  radial-gradient(36% 24% at 40% 38%, color-mix(in srgb,#2A7488 14%,transparent), transparent 64%),
  radial-gradient(32% 22% at 66% 58%, color-mix(in srgb,#6A5B96 12%,transparent), transparent 62%),
  radial-gradient(28% 18% at 30% 66%, color-mix(in srgb,#2A7488 10%,transparent), transparent 60%);
```

另外**深底上亮度变化本身就不明显**：同样是 +14 级，白底几乎看不出，黑底却是翻倍。

#### 三条硬约束（改参数时必须重跑）

| 约束 | 判据 | 现值 paper / night / neon |
|---|---|---|
| 层次不反转 | 卡片均值 − 同高度页面均值 > 2 级 | 15.8 / 18.2 / 18.1 |
| 背景无横向位移 | 所有背景层动画只含 opacity / translateY | 是（paper 完全静止） |
| 文字过 AA | 见下表 | 全部 ≥4.5 |

> 层级与对比度用**实测像素**校验：取样时要把字形像素和 1px 边框排除，
> 否则"文字色 vs 文字自身"会算出 1.00 这种假数据；正确做法是取背景的 5–95 分位。

对比度审计（光斑最坏底色处）：

| 皮肤 | 页上 t2（最坏像素） | 卡上 t3（最坏像素） |
|---|---|---|
| paper | 6.79 | 5.46 |
| night | 8.35 | 6.33 |
| neon | 7.85 | 5.64 |
| contrast | 12.63 | 7.81 |

顶栏正文（`--c-text` 压在 `--c-shell` 上，解析值）：13.55 / 15.45 / 13.54；
三项里最弱的 `--c-text-3` 也有 5.95 / 7.28 / 5.95，全部过 AA。

`neon` 的 `--c-text-2` 就是被这条卡出来的：云把页面最亮推到 `rgb(13,62,74)`，
原值 `#8FA3B8` 只有 4.49，按最坏底色反解提亮到 `#95A8BC` 才到 4.77。

实测动感（390×844，跨一整个动画周期采 9 帧，取区域均值亮度最大变化）：

| 皮肤 | 页面左缝 | 页面右缝 | 格子 | 卡片表面 | 云的空间起伏 |
|---|---|---|---|---|---|
| paper | 16.9 级 | 17.6 级 | 4.3 级 | 5.6 级 | 7.5 级 |
| night | 3.6 级 | 8.7 级 | 3.3 级 | 2.4 级 | 9.4 级 |
| neon | 2.2 级 | 4.5 级 | 5.3 级 | 2.0 级 | 10.2 级 |

「云的空间起伏」= 画面高斯模糊 20px 后背景亮度的标准差。
它是"像云"而不是"均匀雾"的判据：均匀渐变会接近 0，本页是 7–10 级。

> **位移幅度和对比度是解耦的**：幅度只决定"看不看得出在动"，对比度只由 alpha 决定。
> 想更明显就加大幅度（免费），别加 alpha（会击穿 AA 和层次）。

#### 动效强度设置

因为我（实现者）看不到渲染结果，幅度只能靠猜。所以设置页给了三档（`data-motion`）：

| 档位 | `--motion-speed` | 效果 |
|---|---|---|
| 关 | — | `html[data-motion="off"]` 直接 `animation:none`（不能把速度设 0，`calc(时长 / 0)` 是无效值） |
| 柔和 | `.6` | 时长 ÷ 0.6 → 放慢 1.67 倍 |
| 明显 | `1` | 默认 |

偏好存 `localStorage['forager_motion']`，并在**防闪白脚本里也读一次**，
避免首帧以默认速度起跑再跳变。

#### ⚠ 动效与可读性的冲突

光斑会改变页面底色，而**提示文字是直接压在底色上的**（没有卡片底）。
初版光斑让 3 套皮肤的辅助文字跌破 AA（paper 4.63→3.79 / night 4.69→3.63 / neon 4.61→2.78）。

修正：**压在活动背景上的文字一律用 `--c-text-2`**（`.hint` / `.sec-note`），
且 `--c-text-2` 按光斑最坏底色反解，不是按平底。

**规则**：以后调光斑强度，必须重跑上面三条约束；新增任何「直接压在页面底色上」的
文字元素，也要按光斑最坏底色验算。

#### 降级：`color-mix()` 不支持时

`color-mix()` 需要 Safari 16.2+ / Chrome 111+。老浏览器上 `background` 整条无效 →
**卡片直接变透明消失**。所以有一条兜底：

```css
@supports not (background:color-mix(in srgb,#fff 50%,transparent)){
  .card,.tile,.scene-btn{background:var(--c-card)}
  .stat{background:var(--c-page-bg)}
  .skin-btn{background:var(--c-sunken)}
}
```

动效仍在（背景层不用 `color-mix` 也能跑），只是光透不上来。

#### 怎么验证"真的在动"（没有视觉判断能力时）

实现者读不了截图，所以全部靠像素测量。三个踩过的坑：

1. **单帧对拍不可靠**。缓动是 `alternate + ease-in-out`，两端速度趋零；
   恰好在转折点取两帧，会得到"完全没变化"的假结论。
   必须**跨整个周期采多帧**（9 帧 × 2s 覆盖 16s 周期），逐点取 max−min。
2. **单像素噪声大**，受局部梯度斜率影响。大面积用**区域均值亮度**更接近人眼感知。
3. **比较对象要选对**。曾把卡片和"页面"比，结果 y 落进了**底部固定导航栏**
   （不透明 `--c-shell`，比卡片还亮），得出"层次反转 −14.4 级"的错误结论。
   比较必须限定在导航栏以上，且排除凹槽块（`.stat` 本就该比卡片暗）。

#### 纸纹的验收判据

纸纹不能靠"看起来舒服"来判断（实现者看不到）。用可测量的替代指标：

**平坦页面区域内 20×20 窗口的最大亮度落差 ≤ 12 级**。
超过 12 级，规则图案就会开始被眼睛读成"图案/孔洞"；实测当前三套皮肤都是
**0–2 级**（纸浆斑跨度 300px，20px 窗口内几乎没有变化），所以是安全的。

`contrast` 皮肤**任何档位都不动、且表面完全不透明**：
它的价值是极致清晰，飘动和透光是干扰。

### 5.3 首页信息架构：删掉重复，而不是重新排版

首页原来有「情景模式 / 快捷开关 / 能源卡」三块。能源卡里有 6 个指标，其中
**3 个在电池页已有一份**（电池电压、充电电流、发电功率），另外 2 个（剩余容量、
剩余时间）在电池页的库仑计卡里也有一份。也就是说整张卡都是重复数据。

所以处理方式不是"把卡片排紧凑一点"，而是**删掉它**，把"随时要瞄"的少量信息
提升为常驻状态条：

```
顶栏    [FG] FORAGER / 觅食者号 · 485 网关        ● WiFi
状态条  83% ▓▓▓░ │ ▲6.3A │ 剩余 6h53 │ 12:05
首页    情景模式 / 快捷开关                ← 能源卡已删除
电池页  光伏 + 库仑计 + BMS + 趋势          ← 接收全部指标
```

> 曾按提议把能源摘要并进顶栏（92px → 49px，省 43px），但在真机上顶栏一行挤满内容
> 后文字相压，用户最终选择「还是分 2 栏吧，恢复上一个版本」。所以现在是
> **顶栏 63px + 状态条 28px** 的两栏结构：状态条只放电量/电流/续航/时钟，
> 顶栏只放品牌与连接状态。
> 教训：一行塞 7 个信息块在 390px 上不是"紧凑"而是"危险"——真机字体渲染
> 只要宽几个像素就会挤爆。相压的两个真因（flex 的 `min-width:0` 允许子元素溢出、
> iOS text autosizing）仍保留修复，见下。

##### ⚠ 陷阱：顶栏一行挤满内容，手机上会互相覆盖

合并后第一版用 `flex + space-between`，并给 `.hdr-energy` 加了 `min-width:0`。
在桌面 Chrome 里量着刚好放得下，但在真机上文字相压。两个原因：

1. **`min-width:0` 让中间那块可以缩到比内容还窄**，子元素溢出后直接压在时钟上。
   → 顶栏改用 `grid-template-columns:auto minmax(0,1fr) auto` + `overflow:hidden`，
   结构上不可能相压。
2. **iOS 会做 text autosizing**：小字 + 窄屏时自动放大字号，一行布局立刻挤爆。
   → `html{-webkit-text-size-adjust:100%;text-size-adjust:100%}` 显式关掉。

宽度不够时的让位顺序（用媒体查询实现，已验证 320–1024 全部无重叠）：

| 宽度 | 顶栏内容 |
|---|---|
| ≥700px | FG + 品牌字 · 电量 · 电流 · 续航 · 发电 · 电压 · WiFi · 时钟 |
| 431–699px | FG + 品牌字 · 电量 · 电流 · 续航 · WiFi · 时钟 |
| 360–430px | **FG** · 电量 · 电流 · 续航 · WiFi · 时钟（舍品牌字，保住续航） |
| ≤359px | FG · 电量 · 电流 · WiFi · 时钟（再舍续航） |

> 顺序的原则：品牌字是装饰（FG 方块已能识别），续航是信息，所以先舍装饰。

要点：

- **能源摘要放在顶栏**（`.hdr-energy`），四个页面都在，所以首页不需要再放一份。
- **电量进导航栏徽标**（`#navSoc`）作为补充：位置天然（点进去就是电池详情页）。
- **净电流用 `cbCurr`**，不新增"充电/放电"两个字段：它本身就是带符号的
  （正充负放），用一个箭头 ▲/▼ + 颜色表达方向。
- **不用 `SolarChg`**：那是光伏控制器的输出电流，同时带载时与电池净电流差很远
  （发 12A / 负载 5A → 电池只进 7A）。要回答"电池在充还是在放"只能用库仑计。
- **宽屏（≥700px）自动补两格**：发电功率 + 电池电压。手机 3 项、平板 5 项，
  避免大屏上只有 3 项显得空。
- 时钟留在顶栏右端（WiFi 指示灯旁）：它是"扫一眼"信息，和能源摘要同一行不冲突。

> 顺带一个收益：首页删掉大卡后，界面的"活感"可以靠状态条数字滚动提供，
> 背景就不必再"动得明显"——这恰好也缓解了背景一动就像色块的老问题。

### 5.4 neon 皮肤的"科技感"不是靠装饰，是靠三处系统化差异

用户反馈两点：`按钮的透明度太高了` + `字体或者图标是不是也要适配一下这个科技主题`。
结论：科技感要落在**贯穿全皮肤的规则**上，而不是加几块发光。

##### ① 交互面单独一档不透明度（`--surf-alpha-btn`）

卡片可以透（让背景动效透上来），但**按钮不能**：按钮承载文字，透上来会把字糊掉。

```css
--surf-alpha:100%;                       /* 卡片：皮肤决定 50% */
--surf-alpha-btn:var(--surf-alpha);      /* 交互面：默认跟随 */
/* neon */ --surf-alpha-btn:74%;
```

应用到 `.tile` / `.scene-btn` / `.skin-btn`。这个值来回调了两轮才有结论：

| 不透明度 | 按钮底色 | t2 | t3 | 观感 |
|---|---|---|---|---|
| 50%（与卡片同） | rgb(22,29,38) | 6.95 | 5.80 | 网格线从按键里透出来糊住字 |
| 92% | rgb(35,46,59) | 5.64 | 4.71 | 字最清楚，但像死板实心块 |
| **74%（采用）** | rgb(30,39,51) | 6.18 | 5.15 | 字清楚，又能感到背后有东西 |

规律：**交互面的不透明度下限由文字对比度决定（t3 ≥ 4.5），上限由"看起来有没有材料感"决定**，
74% 是这两条约束的交点。

⚠ 踩坑：只加了 `var(--surf-alpha-btn)` 用法、忘了在 `:root` 给默认值 →
`color-mix()` 整条声明失效 → 格子背景变全透明。**新 token 必须先在 `:root` 定义默认值**，
这是第二次踩同一个坑（上一次是 `--bg-fx-ease` 缺失导致动画变 none）。

##### ② 图标：细笔画 + 直角端点

全站图标由同一个 `svg()` 函数生成（`stroke-width="1.4"`、圆端点）。neon 用 CSS 覆盖：

```css
[data-skin="neon"] .ic svg{stroke-width:1.15;stroke-linecap:square;stroke-linejoin:miter}
```

同一套路径，1.4/圆端点 = 手绘感（纸面皮肤），1.15/直角 = 工程图/HUD 感（neon）。
**不要**为某个皮肤重画图标——那会变成两套资产要同步维护。

##### ③ 字：等宽 + 字距

neon 本来只有"数字"是等宽（`--font-num`），标签是比例字体，混在一起不像同一套系统：

```css
[data-skin="neon"] .k, .u, .sec-note, .hint, .bms-age, .stat .k, .chip, nav button{
  font-family:var(--font-num); letter-spacing:.7px; font-variant-numeric:tabular-nums}
```

标签切到等宽后字宽变化 → 必须重跑溢出回归（本轮 6 尺寸 × 4 皮肤 × 4 页面全绿）。

##### ④ 按钮更方：`--r-block` 10px → 6px，`--r-chip` 8px → 4px

直角是 HUD 的默认语言；纸面皮肤保留大圆角。

## 6. 换肤时的附属动作

`applySkin(id)` 除了切 `data-skin`，还会同步：

1. **`meta[theme-color]`** —— 手机浏览器状态栏/地址栏跟着变色
2. **每个 SVG 的 `stroke-width`** —— 高对比皮肤需要更粗的线条
3. **重渲染选择器** —— 更新 `aria-pressed` 与标题旁当前皮肤名

**防闪白**：`<head>` 里有一段内联脚本，在样式生效前就把 `localStorage` 里的皮肤贴到 `<html data-skin>`，避免先画一帧 paper 再跳变。

## 6.5 响应式版式

面板原来只有 430px 单一版式，平板上会被原样拉伸——格子变成 327×60 的窄条，
左右大片空白浪费。现在按屏幕宽度分三档：

| 断点 | 场景 | 版式变化 |
|---|---|---|
| < 600px | 手机竖屏 | 格子 3 列竖排（图标在上、文字在下） |
| ≥ 600px | 平板竖放 / 大手机横放 | 4 列；格子回到接近正方形 |
| ≥ 820px | 平板横放 | **格子横向排版**：图标 → 文字 → 状态点；情景卡横排；能源卡仪表在左、指标 3 列在右；设置页两列并排；内容限宽 1080px 居中 |
| ≤ 520px 高 | 手机横放 | 顶栏去副标题、导航改横排压到底部，把纵向空间让给内容 |

**为什么宽屏要横向排版**：横屏时左右空间远大于上下空间。图标在上、文字在下、
圆点再在下的竖排结构，放进超宽格子里会显得空荡且视线要上下跳；改成
「图标—文字—状态灯」的横向读序后，单行扫读更快，也更符合平板的观看距离。

> ⚠ 媒体查询**顺序有讲究**：`max-height:520px`（矮屏）必须放在 `min-width:820px`
> 之后，否则同等特异性下会被覆盖。这个坑已经在实现中踩到并修正。

## 6.6 页面结构：日志并入设置

「调试」不再占用底部导航 tab（5 → 4 个），实时日志并入设置页并**默认折叠**：

- 标题行即开关（`aria-expanded` + 旋转箭头），点开才加载显示
- 展开状态存 `localStorage['forager_log_open']`；**初始化恢复时不写**，
  只有用户主动点击才持久化，避免默认值被固化成用户选择
- 「打开时自动滚动到底」原先挂在"面板偏好"里很别扭——日志收着的时候它毫无意义，
  现已移进日志面板内部
- 日志区高度从 `calc(100dvh - 300px)`（按整屏算）改为 `clamp(160px,26vh,260px)`：
  它不再是独占一页，而是设置页里的一块
- 平板两列布局下用 `section:has(#logPanel)` 让日志独占整行

## 6.7 尺度契约：只用阶梯上的值

早先每个组件各写各的（7px / 9px / 11px / 22px 混用），单看每处都合理，
合起来就是"说不上哪儿不对但就是不精致"。现在收敛成三套阶梯：

| 类别 | token | 档位 |
|---|---|---|
| 间距 | `--sp-1`…`--sp-6` | 4 / 8 / 12 / 16 / 20 / 24 |
| 光学微调 | `--sp-opt` | 2px（描边、基线、竖条对齐专用，**不参与节奏**） |
| 圆角 | `--r-xs` / `--r-sm` / `--r-chip` / `--r-block` / `--r-card` / `--r-pill` | 6 / 12 / 10 / 18 / 18 / 999 |
| 字号 | `--fs-micro` / `--fs-label` / `--fs-sm` / `--fs-body` / `--fs-val` / `--fs-sec` / `--fs-num` | 10 / 11 / 12 / 13 / 15 / 15 / 24 |

**规则**：组件规则里不写裸 px。装饰性参数例外（点阵大字的 mask 尺寸、`.dot-h` 的字距）
——那些是针对点阵效果逐个调出来的，不走阶梯。

## 6.8 可读性：次要文字必须过 AA

`--c-text-3` 是所有辅助小字（提示、区块注释、未选中导航、stat 标签、单体编号）的颜色，
**一改它整页气质就变**。初版 6 套皮肤里有 5 套不达标（`terminal`/`sand` 后来已删除）：

| 皮肤 | 原 text-3 | 对比度 | 修正后 | 对比度 |
|---|---|---|---|---|
| paper | `#9C9C98` | 2.35:1 ❌ | `#6A6A66` | 4.63:1 |
| night | `#6B7480` | 3.62:1 ❌ | `#7C8692` | 4.63:1 |
| neon | `#4E6279` | 2.84:1 ❌ | `#6B84A0` | 4.61:1 |

> 这就是"看着发闷 / 像蒙了层灰"的量化原因：次要信息几乎不可读，页面读起来是一团灰。

**踩过的坑**：只提 text-3 会让它比 text-2 还深，层级反转。必须**整条灰阶一起上移**：
先把 text-2 提到 ≥6.5:1，再把 text-3 放在 ≥4.6:1 的地板上，两者之间保留可见台阶。
`--c-warn` 当文字用时同样要 ≥4.5:1（paper/sand 原来只有 4.10 / 3.66）。

验收方式：脚本解析 token、按 WCAG 相对亮度公式逐对计算，
对 `page-bg / card / shell` 三个底取**最差值**判定。当前 4 套皮肤 0 项不合规（最低 4.61:1）。

## 6.9 交互态：不糊底色，只改描边与前景

沿用参考稿的规则，并统一到导航：

- 格子 / 情景卡 / 皮肤卡激活 = **描边变色 + 图标变色 + 外侧负扩散柔光**，不换底色
- 底部导航激活**不再**用 `--c-raised` 灰块压底（浅底上发闷、深色皮肤上脏），
  改为 `color-mix(in srgb, var(--c-accent) 8%, transparent)` 淡染 + 强调色图标 + 顶部指示条
- 悬停反馈只在 `@media (hover:hover) and (pointer:fine)` 下生效，触屏不受影响
- 所有可交互元素统一 `:focus-visible` 焦点环（此前只有格子/开关有）

## 6.10 布局溢出：页面级检查会漏

`document.scrollWidth === clientWidth` 只能证明**整页**没撑破，
里面 14px 的溢出会被 `main` 的内边距吞掉。必须逐元素比对内容边界。实测抓到三处：

1. **`.stat-grid` 撑破能量卡 14px** —— flex 子项默认 `min-width:auto`，
   以 min-content 为下限不肯收缩。修：`.stat-grid{min-width:0}` + `.stat{min-width:0}`
2. **`.fold-head` 写 `width:100%`** —— 它在 `.sec-title` 这个 flex 容器里，
   前面还有 3px 竖条 + 8px gap，必然溢出。修：改 `flex:1;min-width:0`
3. **旋转箭头的视觉边框** —— `.fold-chev` 转 45° 后外接盒比布局盒宽约 3px，
   尖端戳出容器。修：给 `.fold-head` 补 `padding-right:var(--sp-opt)`

## 7. 不变的部分（刻意的）

皮肤**不改变**以下行为，这是安全底线：

- 实体映射表（`ENTITIES` / `SENSORS` / `BMS_*` …）与 yaml 的对应关系
- SSE `/events` 订阅与 REST 命令通道
- 页面结构、导航层级、触控尺寸（≥44px）
- 未上线/离线降级逻辑（`--`、虚线占位、数据龄）
- 语义色含义（ok 永远是好，danger 永远是坏）

#### 5.5 neon 的按钮为什么会"死板"，以及怎么修

用户：`neon 首页按钮样式太死板了`。拆开来是三个独立原因，对应三处改动（都只加在 neon）：

| 原因 | 表现 | 改动 |
|---|---|---|
| ① 形状完全均匀，没有结构线索 | 一排排同样的圆角方块 = 网页按钮 | 四角**取景框角标**（HUD 取景框语汇，只是 8 个 1px 渐变，不增加填充） |
| ② 状态只靠描边颜色 | 余光里分不清开/关 | 右下角等宽**状态码 ON / OFF**（9px、字距 1px） |
| ③ 表面纯色平涂 | 像贴纸，不像面板 | 顶部一条主色**受光渐隐**（9% → 透明，46% 处结束） |

配套：状态灯从圆点改成 **1px 描边的方形 LED**（技术语汇里"方"比"圆"更像指示灯），
激活时标签提亮到 `--c-text`。场景卡的"按键"角签改成 `KEY` 工程标注。

```css
[data-skin="neon"] .tile::before{      /* 四角取景框 */
  content:'';position:absolute;inset:0;pointer-events:none;opacity:.3;transition:opacity .18s;
  background:
    linear-gradient(var(--c-accent),var(--c-accent)) left 0 top 0/10px 1px no-repeat,
    linear-gradient(var(--c-accent),var(--c-accent)) left 0 top 0/1px 10px no-repeat,
    linear-gradient(var(--c-accent),var(--c-accent)) right 0 bottom 0/10px 1px no-repeat,
    linear-gradient(var(--c-accent),var(--c-accent)) right 0 bottom 0/1px 10px no-repeat;
}
[data-skin="neon"] .tile.on::before{opacity:1}   /* 开 → 角标全亮 */
[data-skin="neon"] .tile::after{content:'OFF';font-family:var(--font-num);font-size:9px}
[data-skin="neon"] .tile.on::after{content:'ON';color:var(--c-accent)}
```

**为什么不做切角（clip-path）**：切角会裁掉 `box-shadow`，而 neon 激活态的发光正是靠
`box-shadow:var(--glow-tile)`；角标能达到同样的"技术感"，还能保住发光。

⚠ 注意 `.tile.on` 里写了 `background:var(--c-card)`（shorthand），会把背景图清掉；
neon 的受光渐隐写在其后、同特异性，靠**源码顺序**取胜。以后调整顺序要复查这一点。

#### 5.6 neon 按钮的"活气"：按下手感 + 角上读数

用户批准的两个方向（A + B）。

##### A. 按下微动效（纯 CSS，40 行）

```css
[data-skin="neon"] .tile:active::before{opacity:1;transition-duration:0s}  /* 角标瞬间全亮 */
[data-skin="neon"] .tile:active .ic{transform:scale(.94)}                  /* 图标回缩 */
[data-skin="neon"] .tile:active{box-shadow:inset 0 0 0 1px var(--c-accent)}/* 内描边压一层 */
```

关键点是**「瞬时」**：角标用 `transition-duration:0s` 直接跳到全亮，不做渐变。
按下的反馈必须是即时的，任何 100ms 以上的渐变都会被读成"卡"。

##### B. 角上读数：`ON 3m` / `OFF`

设备没有提供**每个回路**的功率，所以读数用「已开启时长」——真实可解释，
比编一个假瓦数诚实。实现：

- 格子模板里加一个真实元素 `<span class="tv">`（不能用 `::after`，因为内容是动态的）
- `SINCE[k]` 记录每次变 ON 的时间戳，`updateTileReadouts()` 每 10s 刷一次
- 时长格式：`<60s → 30s`、`<60m → 12m`、再往上 `1h05`
- `.tv` 默认 `display:none`，只有 neon 打开；其他皮肤仍是纯图标格子

```js
function updateTileReadouts(){
  document.querySelectorAll('.tile[data-key]').forEach(t=>{
    const k=t.dataset.key, on=!!state.switches[k], tv=t.querySelector('.tv');
    if(!tv) return;
    if(on){ if(!SINCE[k]) SINCE[k]=Date.now();
            tv.textContent='ON '+fmtDur(Date.now()-SINCE[k]); }
    else  { delete SINCE[k]; tv.textContent='OFF'; }
  });
}
```

⚠ 已知局限：读数从**页面加载后**开始计时，刷新会归零（设备不带"开启时刻"字段）。
如果以后固件在开关实体上暴露 `last_changed`，这里直接换成真实时间差即可。

##### 为什么不做"切角 / 3D 凹凸 / 拟物按键"

- 切角会裁掉 `box-shadow`，而 neon 激活态发光全靠它
- 凹凸/拟物与"点阵 + 线条"的平面语言冲突（前几轮已经因为"色块""密集"被否过）

按钮的"活"来自**状态可见 + 反馈即时**，不是来自材质堆叠——这是这一轮的核心结论。

#### 5.7 第五款皮肤 `ios6`：拟物化 / iOS 6

前四款（paper / night / neon / contrast）都是**平面**语言，靠留白、线条、明度分层次；
`ios6` 换的是**维度**——靠高光、阴影、渐变让每个表面"有厚度"。

##### 三条贯穿全皮肤的规则（比任何单点效果都重要）

1. **亮面在上、暗面在下**：所有渐变统一 `180deg`，光从上方来。
2. **每个凸起 = 1px 白色内高光 + 1px 深色下沿**：
   `box-shadow: 0 1px 0 rgba(255,255,255,.95) inset, 0 -1px 0 rgba(0,0,0,.07) inset`
3. **激活/开启 = 换成同一块蓝玻璃**：`linear-gradient(180deg,#2E86DA,#0E63C4 50%,#0A52A6)`
   文字变白并带 `text-shadow:0 -1px 0 rgba(0,0,0,.35)`。

只要所有组件都遵守同一个光源和同一块蓝玻璃，即使零件很多，看起来仍是一套系统，
而不是逐个零件贴图。

##### 材质清单

| 表面 | 材质 |
|---|---|
| 页面底 | 顶部白光 + 1px/5px 横向拉丝（`repeating-linear-gradient`），**静态** |
| 顶栏 | 蓝灰塑料条 `#6E839D → #4E6379 → #415267`，白字带向下投影 |
| 状态条 | 浅银面 `#F8FAFC → #D8DFE8`，深字 |
| 卡片 | 白瓷面 + 发丝描边 `#9AA5B1` + 顶部高光 |
| 按键 | 上亮下暗塑料面 `#FFF → #F2F5F8 → #DDE3EA` |
| 按键·开 | 蓝玻璃（同上），白字 |
| 底栏 | 深玻璃条 `#5E6E82 → #2E3A48`，激活项底部 22px 白色短亮条 |

##### 拟物化最容易栽的两件事

**① 对比度：光泽会偷走对比度。**
白色内高光、顶部渐亮都在"往底色里掺白"，文字对比度会悄悄掉到 4.5 以下。
本项目实测踩到两处：

- 顶栏初版 `#93A7C1 → #55697F`，白字只有 **3.23** → 压暗到 `#6E839D → #415267`，升到 **9.33**
- 页面次要文字 `--c-text-3:#575757` 在 `#C7CED6` 底上只有 **4.4** → 加深到 `#4A4A4A`

**② 组件选色不能按"看起来对"来，要按"落在哪个底上"来。**
顶栏副标题 `.bs` 沿用了正文的 `--c-text-3`，落在深色顶栏上变成深灰对深蓝，
对比度 **1.41**（几乎不可见）。修法是把 `.bs` 一起纳入顶栏白字组。

> 教训：新增皮肤时，凡是"同一 token 在不同底色上复用"的组件都要单独验一遍。
> 这轮的自动化手段是——截图后取文字框内 **3% / 97% 分位**（字形 vs 底色）算对比度，
> 而不是取整块区域（整块会把背景和图表算进去，得到假数字）。

##### 终值（像素实测）

| 位置 | 对比度 |
|---|---|
| 蓝玻璃按键 白字 | 10.38 |
| 白塑料按键 深字 | 12.50 |
| 顶栏 品牌白字 | 9.33 |
| 顶栏 副标题白字 | 10.31 |
| 底栏 激活白字 | 10.45 |

回归：5 种尺寸 × **5 款皮肤** × 4 页面零越界、零 JS 报错；皮肤选择器 5 项、
localStorage 持久化正常。

#### 5.8 第六款皮肤 `ios26`：Liquid Glass + 两个真实踩坑

用户：`底栏未选中的图标看不清` + `再加一个 ios26 玻璃效果`。

##### A. ios6 底栏图标不可见的真因：子元素自带颜色

`nav button{color:...}` 只影响按钮本身；图标是子元素 `.ic`，它有自己的一条
`color:var(--c-text-3)`。在 ios6 里 `--c-text-3` 是深灰 `#4A4A4A`，落在深色底栏上 = 隐形。

```css
[data-skin="ios6"] nav button .ic{color:#D8E1EA;opacity:1}
```

> 教训：**给容器改色不等于给子元素改色**。凡是"容器 set 了 color、子元素又有自己的
> color 规则"的地方（`.ic` / `.mark` / 数值 span），换皮肤都要一并覆盖。

另外，验证时遇到 `rgb(97,97,93)` 这种"不存在的颜色"，其实是 `transition:color .15s`
的**中间态**。测量皮肤切换后的颜色必须等过渡走完（≥300ms），否则会追一个假 bug。

##### B. ios26 玻璃：折射 + 棱线 + 大圆角，缺一不可

| 要素 | 实现 |
|---|---|
| 折射 | `backdrop-filter:blur(18px) saturate(180%)`（Safari 要 `-webkit-` 前缀） |
| 棱线 | `inset 0 1px 0 rgba(255,255,255,.98)` + `inset 0 0 0 1px rgba(255,255,255,.45)` |
| 悬浮 | `0 10px 26px -16px rgba(16,32,64,.5)` |
| 形体 | `--r-card:26px; --r-block:18px; --r-chip:999px`（胶囊） |
| 选中态 | **染色玻璃**（`rgba(10,132,255,.22)` + 深蓝字 `#0A4E9E`），不是填满强调色 |

选中态为什么不用"填满蓝 + 白字"：白字在 82% 不透明度的 `#0A84FF` 上只有 ~3:1 左右，
AA 不达标；染色玻璃 + 深蓝字实测 **6.21**，而且更像 iOS 26 的做法。

老 WebView 没有 `backdrop-filter` 时会退化成 `rgba(255,255,255,.9)` 的实色，
否则玻璃变成"半透明纸"，字会糊。`@supports` 要同时判断带前缀与不带前缀的写法，
否则 Safari 会被误判成不支持、直接掉到兜底。

##### C. 最贵的一课：CSS 里一个多余的引号，吞掉了整段样式

写 ios26 规则时手滑打出：

```css
[data-skin="ios26"] .log{"--glass-blur:18px;}
```

`{` 后面那个 `"` 开启了一个字符串，CSS 解析器把它当成**未闭合的字符串**，
于是把它之后的所有规则（整个 ios26 玻璃块、`@media(prefers-reduced-motion)`）
全部吞进字符串里丢弃。文件本身是"合法"的（括号/注释都配平），只是**运行时少了一大段**。

两个代价惨重的观察：
1. **布局回归全绿**——规则没了不会导致溢出，`5 尺寸 × 6 皮肤 × 4 页面` 依然全过。
2. **只有比对"计算值"才暴露**：`getComputedStyle(card).backdropFilter === 'none'`、
   阴影只剩 `--shadow-card`。

因此回归脚本新增 **CSS 健康检查**：遍历 `document.styleSheets` 递归统计规则总数，
并断言几条关键规则（关闭动效、玻璃、某皮肤专属）确实存在。
当前基线：**375 条规则 / 6 款皮肤**。

##### 终值（ios26 像素实测）

| 位置 | 对比度 |
|---|---|
| 玻璃格子 深字 | 13.00 |
| 染色玻璃 选中字 | 6.21 |
| 底栏未选中图标 | 5.65 |
| 底栏未选中标签 | 5.57 |

回归：5 尺寸 × **6 皮肤** × 4 页面零越界、零 JS 报错；CSS 375 条规则、关键规则全部在位。

#### 5.9 状态条：电量改成分格电池 + 玻璃接缝修复

用户：`顶栏跟电池这里不好看，好像隔着几个像素的白色边框`、`电池多少能否直接放在 icon 里，不要数字，用格子`。

##### A. 电量分格的位置：底栏 tab，不是状态条

第一版我把状态条的数字换成了电池分格——**搞反了**。用户的原意是：

| 位置 | 显示 | 理由 |
|---|---|---|
| **状态条**（顶栏下面那条） | 数字 + `%` + 4px 细条 | 一眼要读到精确值（"还剩 78%"），细条只是趋势 |
| **底栏电池 tab 的电池图标** | **图标本身就是 5 格** | 不额外加徽标：电量画在电池图标里面，图标自己会说话 |

```html
<!-- 状态条：数字 + 细条（保持原样） -->
<b id="sbSoc">78</b><span class="u">%</span>
<i class="sb-track"><i class="sb-fill" id="sbFill"></i></i>

<!-- 底栏 tab：5 格 -->
<span class="nav-badge" id="navSoc" role="img" aria-label="电量"><i></i>×5</span>
```

- 5 格 = 每格 20%，`lit = ceil(pct*5/100)`，不为 0 就至少亮一格
- 未点亮格 `opacity:.24`；格子尺寸 2.5×7px、间距 1px、圆角 .5px
- 颜色仍走 `battColor()` 语义分级；**数字只留给读屏和悬停**（`aria-label` + `title`）

⚠ 实现坑：徽标的格子是 `<i>` 子元素，所以渲染时**绝对不能**写
`$('navSoc').textContent = pct+'%'` —— `textContent` 会清空所有子节点，
5 个格子被冲掉、徽标又变回文字。正确做法是切 `on` class，数字只写 `aria-label`。

分格实测：`0/5/20/21/50/81/100% → 0/1/1/2/3/5/5 格`。

##### B. 玻璃接缝：三层白棱线叠成了"几像素的白框"

顶栏和状态条在 ios26 里都是玻璃，各自带：
1. `border:1px solid rgba(255,255,255,.72)`（四周白边）
2. `inset 0 1px 0 rgba(255,255,255,.98)`（顶部内高光）
3. 各自的渐变底部

两者上下相接 → 接缝处叠出 **3px 左右的白带**，读起来就是"隔着一个白框"。

修法：**相接的边全部去掉，只保留外侧边**。

```css
[data-skin="ios26"] header{border-bottom:0; box-shadow:inset 0 1px 0 rgba(255,255,255,.98), 外侧投影}
[data-skin="ios26"] .statusbar{border-top:0; box-shadow:none; border-bottom:1px solid rgba(16,32,64,.10)}
```

注意最后那条：**与内容的交界用"暗发丝"而不是白线**。亮色玻璃上，1px 白线同样会被读成
"多出来的边框"；换成 10% 的深色发丝反而像玻璃的边缘。

修完像素实测：接缝处上行亮度 230、下行 231（无缝），全部近白行数为 **0**。
ios6 也顺手去掉了状态条顶部的白色内高光（它紧贴深色顶栏，同样会显出一道白线）。

##### C. 换皮肤后语义色不更新

电量分格的颜色来自 `battColor()` → `cssVar('--c-ok')`，是在**渲染那一刻**读 CSS 变量的。
换皮肤只改 `data-skin`，不会触发重绘逻辑 → 电池会一直用上一款皮肤的绿色（直到下一条 SSE）。

修法：`applySkin()` 末尾调用一次 `renderPower()`。

##### D. 又一次被 transition 骗到（第 3 次）

换皮肤后立刻读 `getComputedStyle(batt).color`，得到的是**过渡中间值**（`.sb-batt` 上有
`transition:color .4s`），看起来像"换皮肤没生效"。

> 定为硬规则：**任何换皮肤后的颜色断言，必须等 ≥400ms**。
> 布局/几何可以立刻读，颜色/阴影不行。

#### 5.10 底栏电量画进图标 + 分段控件统一 + 玻璃状态条精修

用户三点反馈，前两点是"位置/层级错了"，第三点是组件材质不统一。

##### A. 底栏电量：不是加徽标，是**改电池图标本身**

上一版在 tab 图标旁边加了个 5 格小徽标 —— 仍然"多长出来一块"。正确做法是把
`navBat` 图标换成带 5 格的电池 SVG，靠 `opacity` 点亮：

```html
<span class="ic nav-batt" id="navBatt" role="img" aria-label="电量">
  <svg viewBox="0 0 24 24">
    <rect x="2.2" y="6.8" width="17.2" height="10.4" rx="2.6"/>   <!-- 外壳 -->
    <path d="M21.6 10.4v3.2"/>                                    <!-- 正极 -->
    <rect class="cell" x="4.2" …/> ×5                             <!-- 5 格 -->
  </svg>
</span>
```

```css
.nav-batt .cell{fill:currentColor;stroke:none;opacity:.2;transition:opacity .3s}
.nav-batt .cell.on{opacity:1}
```

图标 SVG 直接写在 HTML 里（不用 `data-icon` 注入），这样不会被图标工厂覆盖；
`applySkin()` 统一改描边宽度时它也会跟着变。

##### B. 为什么这几个按钮的文字会【竖排】

`.seg .chip` 原来是 `flex:1` —— 在 `justify-content:space-between` 的行里会被压窄，
而中文每字一个断行点，宽度不够就变成"一列字"。

```css
.seg .chip{flex:1 1 auto; white-space:nowrap}
```

修完实测：`关 37px / 柔和 51px / 明显 51px`、`white-space:nowrap`，三枚并排单行。

##### C. 分段控件：凹槽 + 凸起，而不是三块飘着的白片

用户：`外面有圆角，有背景，这一层又是直角，又是白色背景`。
原因是 `.seg` 是个透明容器、`.chip` 各自实心白，看起来就是"白块贴在玻璃卡片上"，
既没有控制器的整体感，也和玻璃材质打架。

iOS 的做法是**两件套**：外层是凹槽（内阴影），选中片才抬起来。

```css
[data-skin="ios26"] .seg{
  padding:2px;border-radius:999px;background:rgba(11,18,32,.07);
  box-shadow:inset 0 1px 2px rgba(16,32,64,.18), inset 0 -1px 0 rgba(255,255,255,.5);
}
[data-skin="ios26"] .seg .chip{background:transparent;border:0;box-shadow:none;border-radius:999px}
[data-skin="ios26"] .seg .chip.active{background:rgba(255,255,255,.96);box-shadow:0 1px 2px rgba(16,32,64,.22)}
```

ios6 用同一套结构、换塑料语汇：凹槽 `linear-gradient(#AEB8C2,#D6DCE2)` + 内阴影，
选中片是蓝玻璃渐变。

顺带把卡片里单独出现的 `.chip`（重启 / 打开 / 暂停 / 清空）也改成半透明玻璃
`rgba(255,255,255,.55)`，不再实心白——它们在同一张玻璃卡片里，实心白会"跳出来"。

##### D. ios26 状态条：一排数据 + 三条竖线 = 碎

- 去掉 `.sb-sep` 竖分隔线，改用 `gap:14px` 分组
- 数字 `font-variant-numeric:tabular-nums` + 字距 -0.2px，单位压暗到 `--c-text-3`
- 细条 38×4 → 30×3，底色改成 12% 深色（亮玻璃上更稳）
- 状态条底色由"两段渐变"改为更平的一层（顶部和顶栏渐变叠加后会显得发灰）

##### 验证

- 5 尺寸 × 6 皮肤 × 4 页面零越界、零 JS 报错
- 新增 `TXT-WRAP` 检查：任何 chip 的 `scrollHeight > clientHeight` 即判定文字折行
- 新增"直角白块"扫描：设置页内 `background` 接近纯白且 `radius<2px` 的元素
  （只剩皮肤选择器里被父级 `overflow:hidden` 裁圆的三色色条，属正常）
- CSS 390 条规则（无解析损失）

#### 5.11 电池外壳跟主题 + 设置行的"直角白框"真凶

##### A. 电池：外壳跟主题，只有格子带语义色

上一版整个图标都用 `battColor()` 染成绿/琥珀/红 → 底栏里凭空多一块彩色，**很突兀**。

拆成两层：

```css
.nav-batt .shell{stroke:currentColor}          /* 外壳 = 底栏该项的字色（主题/选中强调色） */
.nav-batt .cell{fill:var(--batt-col,currentColor)}  /* 格子 = 语义色 */
```

```js
nb.style.setProperty('--batt-col', battColor(pct));   // 只给格子
// 不再 nb.style.color = battColor(pct)
```

实测：ios26 未选中外壳 `rgb(85,98,116)`（主题次要色）、选中 `rgb(10,95,192)`（强调蓝），
格子始终 `rgb(27,127,69)`（绿）。整枚图标不再"独立于主题"。

##### B. 设置行的白框：`.set-row` 被玻璃选择器误伤

用户：`系统与维护几个配置项还是直角加背景色不协调`。

真凶不是 chip，是 **`.set-row` 自己**。玻璃皮肤的选择器是一长串：

```css
[data-skin="ios26"] .card, .tile, .stat, .set-row, .chip, … {
  border:1px solid rgba(255,255,255,.72); border-radius:…; box-shadow:…;
}
```

`.set-row` 混在这串里 → 每个设置行都得到 **1px 白边 + 直角**，
于是 26px 圆角卡片里套了一排"小方框"，行与行之间白线还互相压着。
ios6 的瓷白规则里也误带了 `.set-row` → 同样的方框（还更明显，因为它是实心白）。

修法两步：

1. 把 `.set-row` 从这两处的选择器组里**摘掉**
2. 再显式声明它的正确定位：

```css
[data-skin="ios26"] .set-row{
  background:none;border:0;border-bottom:1px solid rgba(11,18,32,.10);
  border-radius:0;box-shadow:none;backdrop-filter:none;
}
[data-skin="ios26"] .set-row:last-child{border-bottom:0}
```

> 教训：玻璃/瓷白这类"给一大串元素统一加边框阴影"的规则，**只能列真正的卡片
> 级元素**。行、工具栏、内联容器一旦混进去，就会得到"卡片内部的卡片轮廓"，
> 表现为直角白框。加进选择器列表前先问一句：这个元素本身就是一张卡片吗？

##### 验证

- 6 皮肤 × 设置页扫描：`.set-row` 上/左/右边框宽度 = 0、底色透明、无投影、无圆角
- 5 尺寸 × 6 皮肤 × 4 页面零越界、零 JS 报错
- CSS 395 条规则（无解析损失）

#### 5.12 ios26 状态条：从"一排数字"改成"分组读数"

用户：`整体好很多，唯一的问题还是顶栏下面的电池信息相关这里不好看`。

上一版的状态条是"一排右对齐的数字 + 三条竖线"：电量、电流、剩余时间权重相同，
眼睛不知道该先读哪个；而且 78% 的**数字和细条是分离的两截**，看着像两个控件的残余。

改成 iOS 的分组读数，**层级 = 药丸 > 小字**：

```css
[data-skin="ios26"] .statusbar{justify-content:flex-start;gap:8px}   /* 不再均匀铺开 */
[data-skin="ios26"] .sb-main{                                        /* 电量药丸 */
  gap:4px;padding:3px 9px 3px 10px;border-radius:999px;
  background:rgba(255,255,255,.72);box-shadow:inset 0 1px 0 #FFF,0 1px 2px rgba(16,32,64,.10);
}
[data-skin="ios26"] .sb-cur{padding:3px 9px;border-radius:999px;background:rgba(255,255,255,.46)}
[data-skin="ios26"] .sb-clock{margin-left:auto}                        /* 时钟唯一靠右 */
```

要点：

1. **数字和细条必须在同一个药丸里**——它们是同一个读数，分开就变成两个控件
2. 电量药丸 `rgba(255,255,255,.72)` 是**第一层**；电流药丸 `.46` 是第二层，
   靠透明度区分主次，而不是靠字号喊
3. 电流数值不再染色，只让方向箭头带语义色（充绿/放琥珀）——整行染色会显得脏
4. `justify-content:flex-start` + 时钟 `margin-left:auto`：左侧读数是"一组"，
   右侧时钟是"另一个信息"，比 `space-between` 把 6 项均匀撒开清楚
5. 状态条底色改成偏冷的浅蓝渐变，和顶栏的亮白拉开一点点（不加任何描边，
   避免又叠出白框）

实测 390/320/768/1280 四档：条高 32px、零溢出、零分隔线、
状态条内元素零重叠（新增 `SB-OVERLAP` 检查）。

> 仍未定：这是第 4 次调整这一条。如果还不对，需要用户指明是
> "信息太多 / 排版形态 / 与顶栏分层 / 干脆不要这条"，再动手；
> 靠猜只会来回改。

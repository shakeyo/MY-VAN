# 设计决策：智能控制与交互系统

## 📋 方案概述

本方案构建一套**"N100 中枢 + ESP32 485 网关 + 分布式继电器终端"**的三级智能控制系统。核心逻辑是**"计算中心化、控制去中心化、冗余机械化"**。

**关键澄清**：ESP32 运行 ESPHome 固件，作为 Home Assistant 的无线节点和 485 总线网关，**不是 HA 主机**。HA Core 运行在 N100（PVE/LXC）上，负责自动化、场景、远程访问、数据汇总。ESP32 负责将 HA 的指令转换为 485 总线信号，并采集总线设备状态回传 HA。

## 🏗️ 系统架构

```
┌─────────────────────────────────────────────────────────┐
│  N100 (PVE/LXC)                                         │
│  ├── Home Assistant Core      ← 自动化中枢、场景引擎      │
│  ├── Frigate                  ← AI 视频监控              │
│  └── MQTT Broker              ← 消息总线                 │
└────────────┬────────────────────────────────────────────┘
             │ WiFi / LAN
┌────────────▼────────────────────────────────────────────┐
│  ESP32 (ESPHome)                                         │
│  ├── WiFi 接入 HA                                         │
│  └── UART ↔ MAX485 ↔ RS485 总线                          │
└────────────┬────────────────────────────────────────────┘
             │ RS485 手拉手总线
    ┌────────┼────────┬────────┬────────┐
    ▼        ▼        ▼        ▼        ▼
 485继电器  485继电器  485继电器  485传感器  485传感器
 (10路)     (10路)     (10路)    (温湿度)  (电量计)
    │        │        │
```

## 🔌 电力拓扑

### 1. 原车电瓶系统 (12V Starter)
- **负责**: 发动机启动、原车车机、原车安防报警。
- **接入**: 行车充电器输入端、360 全景主机。

### 2. 生活区副电瓶系统 (12V House)
- **负责**: 所有改装设备 (N100、路由器、摄像头、灯光、水泵、逆变器、ESP32、485 模块)。
- **核心连接**: 从副电瓶引出 10AWG/4mm² 红黑双线作为"常电干线"，直达驾驶室中控台和生活区配电点。

## 📶 网络拓扑

- **核心网关**: GL.iNet/Cudy 工业路由器 (副电瓶常电供电)。
- **WAN 接入**: 4G/5G CPE 或手机热点。
- **LAN 节点**:
  - **有线**: N100 (HA)、DVR 编码器。
  - **无线 (固定 IP)**: 安卓车机、ESP32。

## 🕹️ 交互控制区域

### 1. 驾驶室 (Cab Zone)
- **目标**: 安全、盲操、能源管理。
- **硬件**:
  - **自复位按钮 (带 LED)**: 6-8 个，接入 485 继电器模块的按键输入端口。
  - **控制项**: 逆变器总开关、行车充电器、水泵电源、场景切换、车外射灯。
  - **显示**: 安卓车机 (Fully Kiosk)，显示电量 %、水位 %、360 画中画。

### 2. 生活区 (Living Zone)
- **目标**: 舒适、全面、本地强控冗余。
- **硬件**:
  - **多路翘板开关/自复位按钮**: 门口、床头、厨房等操作点位。
  - **执行器**: 485 Modbus 继电器板（带物理按键输入端口）。

## 🔄 双控逻辑（核心决策）

### 维护模式 (Maintenance Mode)
- **逻辑**: 物理按钮直接接在 485 继电器模块的按键输入端口，按钮触发继电器吸合/断开，**完全不依赖 ESP32 或 HA**。
- **用途**: 系统故障、HA 宕机、网络中断时，仍可通过物理开关控制全车负载。
- **实现**: 选择**带按键输入的 485 继电器模块**，按钮一端接模块 GND，另一端接模块按键 IO。

### 智能模式 (Smart Mode)
- **逻辑**: HA 下发指令 → ESP32 通过 485 总线发送 Modbus 指令 → 继电器模块执行 → 模块回传状态 → HA 更新状态。
- **用途**: 远程控制、自动化场景、定时任务、状态监控。
- **状态同步**: ESP32 定时轮询所有继电器模块状态（1-2s 间隔），确保 HA 面板与物理开关状态一致。

## 🔗 485 总线拓扑（关键规范）

- **拓扑方式**: 手拉手串联，**严禁星型或分支**。
- **总线末端**: A/B 之间并联 **120Ω 终端电阻**（首尾各一个）。
- **屏蔽层**: 单端接地（仅 ESP32/主控端接地，末端悬空）。
- **波特率**: 9600（稳定性优先）。
- **供电**: 继电器模块使用 12V 车载电源；ESP32 使用 5V 稳压供电。
- **地址分配**: 每个 485 模块设置唯一地址（1、2、3...），禁止重复。

## 📡 传感器拓展

所有传感器通过 485 总线并联接入，不占用 ESP32 GPIO：

| 传感器类型 | 接入方式 | 用途 |
|-----------|---------|------|
| 温湿度传感器 (RS485) | 并联总线 | 车内/储物仓环境监测，联动风扇 |
| 电量计 (PZEM-017) | 并联总线 | 蓄电池电压、电流、功率监测 |
| 水箱水位 (RS485/干接点) | 并联总线或模块 DI 口 | 清水/灰水箱液位 |
| 门磁/人体感应 | 模块 DI 输入口 | 开门亮灯、有人启动通风 |
| 漏水传感器 | 模块 DI 输入口 | 底盘漏水、窗边淋雨报警 |

## 🎥 视觉监控系统

- **目标**: 全车 AHD 监控网络化分发 + AI 识别。
- **信号处理**: Y 型转接线并联原车摄像头信号 → DVR 编码器 → RTSP 网络流。
- **处理单元**: N100 运行 Frigate，进行人形/车辆 AI 识别。
- **展示层**: HA Dashboard 在手机、平板、安卓车机上显示。

## 🔊 全景声音响系统

- **核心**: 阿尔派 R600 8 路 DSP 功放。
- **布局**: 前门 DM65C 两分频 + 后门 DM65 同轴 + PWE-S800 超薄低音炮。
- **声场模式**: 驾驶 / 影院 / 派对（通过 DSP 预设切换）。

## 🚗 汽车数据集成 (OBD-II)

- **方案**: ELM327 (蓝牙) → 安卓车机 (Torque Pro + MQTT) → HA。
- **联动**: RPM > 500 自动启停行车充电；电压跳变触发迎宾模式。

## 🛠️ 实施顺序

1. **阶段一**: 网络与中枢搭建（N100 + 路由器 + HA）。
2. **阶段二**: 485 总线与继电器模块安装（生活区优先）。
3. **阶段三**: ESP32 网关部署与 ESPHome 烧录。
4. **阶段四**: 驾驶室按钮面板安装与穿线。
5. **阶段五**: 传感器接入与 HA 自动化配置。
6. **阶段六**: 安卓车机 + Dashboard + 音响调试。

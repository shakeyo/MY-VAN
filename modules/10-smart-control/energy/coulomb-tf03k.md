## 一、设备信息（实测协议确认）

| 项 | 值 |
|----|-----|
| 型号 | **TF03K 库仑计（Battery Capacity Tester）** |
| 通信 | TTL 串口 / RS485 两种物理接口（可选配 RS485 版） |
| **波特率** | **19200 bps** ⚠️ 全车 485 总线为 9600，两者不能同线 |
| 数据长度 | **16 字节 / 次** |
| 发送周期 | **1 次 / 秒**（仅在库仑计工作时发：有充放电流 或 背光点亮） |
| 接口电平 | TTL 侧 5V；RS485 侧接 A/B/GND，**产品内部已配 120Ω 终端电阻** |
| 隔离方式 | 光耦隔离 + 电源模块隔离 |
| **接收命令** | **无**（仅 TXD 主动发送，RXD 无接收功能，可不接；批量客户可定制） |
| 校验和 | **第 1~15 字节的 8 位累加和**（非 CRC16） |
| 从站地址 | **无**（不是 Modbus，无地址寻址） |

## 二、数据帧格式（16 字节，逐字节定稿）

**帧头 `0xA5` → 电量百分比 → 电压 → 容量 → 电流 → 剩余时间 → 校验和**

| 字节 | 数值名称 | 示例 Hex | 举例说明 | 数值范围 | 解析规则 |
|------|----------|----------|----------|----------|----------|
| **1** | 索引字节 | `A5` | `A5` | `A5` | 帧头固定 `0xA5`（兼作帧同步字节） |
| **2** | **电量百分比** | `02` | `0x02 = 2%` | `0 ~ 100%` | 直接为百分比，无需换算 |
| **3-4** | **电池组总电压 (V)** | `07 D0` | `0x07D0 = 2000 = 20.00V` | `0 ~ 500.00V` | 大端 16 位，**÷100** |
| **5-8** | **当前电池容量 (mAh)** | `00 00 0A 87` | `0x00000A87 = 2695mAh = 2.695Ah` | `0.1Ah ~ 5000Ah` | 大端 32 位（mAh），**÷1000 → Ah** |
| **9-12** | **电池电流 (mA)** | `00 00 24 05` | `0x00002405 = 9221mA = 9.221A` | `-750000 ~ +750000 mA` | 大端 32 位有符号；**负值为补码**（充/放方向需实测确认） |
| **13-15** | **剩余时间 (秒)** | `00 94 11` | `0x009411 = 37905s = 10:31:45` | `00:00:00 ~ 99:59:59` | **大端 24 位（3 字节全用）**，单位秒，换算 hh:mm:ss |
| **16** | **校验和** | `XX` | 第 1~15 字节累加和 | 8 bit | 累加和取低 8 位比对 |

> **帧长自洽**：1(帧头) + 1(SOC) + 2(电压) + 4(容量) + 4(电流) + 3(时间) + 1(校验) = **16 字节** ✅

### 完整示例帧（按手册示例值构造，已复算校验和）

```
A5 02 07 D0 00 00 0A 87 00 00 24 05 00 94 11 DD
│  │  └─┬─┘ └────┬────┘ └────┬────┘ └──┬───┘ └┬┘
│  │    │        │           │         │      └ 校验和 = 前15字节累加和低8位 = 0xDD
│  │    │        │           │         └ 剩余时间 0x009411 = 37905s = 10:31:45
│  │    │        │           └ 电流 0x00002405 = 9221mA = 9.221A
│  │    │        └ 容量 0x00000A87 = 2695mAh = 2.695Ah
│  │    └ 电压 0x07D0 = 2000 → 20.00V
│  └ SOC = 0x02 = 2%
└ 帧头
```

> 实测时对应用例：把上面 16 字节作为比对基准，抓到的真实帧应满足同样结构（数值可不同）。
> 若累积和校验逐字节算出来等于帧尾字节，即解析逻辑正确。

### 需要实测确认的一点

1. **电流方向**：协议只写"负值为补码"，未明确"充电为正还是放电为正"。**上电实测**（充电时看符号）后在此补结论。

> 字节 13-15 位数分配已通过读原图确认（**3 字节全用**，`0x009411` 按 24 位大端解析），无需再猜。

## 三、帧解析建议（ESPHome lambda）

思路与 [base.yaml](../gateway/esphome/base.yaml) 里 `read_upload` 同构：**扫描 RX 缓冲 → 找帧头 → 验累加和 → 解析 publish**。

```cpp
// 伪代码，落到 pzem-tf03k.yaml 时展开
// 1. 读空 UART 缓冲到 static buf[len]，保留残帧到下一 tick
// 2. 在 buf 中找 0xA5 起点，若剩余 < 16 字节则 break（等下一 tick 补齐）
// 3. 累加和校验：sum(buf[i..i+14]) & 0xFF == buf[i+15]
// 4. 校验通过后按上表解析，publish 到 sensor
```

要点：
- **1 次/秒**，可用 `interval: 200ms` 扫描缓冲，无需高频。
- **不需要** DE 方向控制（库仑计只发，网关只收）→ 直接用普通 `uart` 读，**不走 `rs485_write`**。
- 残帧处理必须做（与 `read_upload` 同理，避免一帧切两半丢数据）。

## 四、总线与接线

### 为什么有 RS485 还要单独一个 UART

RS485 是**物理层**（差分传输，抗干扰），UART 是 **MCU 内部的串口外设**。两者不是替代关系——
485 信号最终仍要落到某个 UART 引脚上，收发器只是中间的转换：

```
TF03K ──A/B 差分──> MAX3485 ──TTL 电平──> ESP32 的 UART 外设
       (物理层)                    (必须占用一个 UART)
```

**不能并入全车 485 总线**，是三条硬冲突（与是否有 485 无关）：

| 冲突项 | 全车 485 总线 | TF03K |
|--------|--------------|-------|
| **波特率** | 9600（终局，由 MPPT 上限决定） | **19200** |
| **协议** | Modbus RTU（主从、CRC16） | **私有帧、主动上报、8 位累加和** |
| **方向** | 双向（主站轮询） | **只发不收** |

同一根 A/B 线上只能有**一个波特率**。19200 与 9600 混挂 → 双方全部乱码。
故库仑计必须走**另一对 A/B 线 + 另一个 UART**。

### 接线拓扑

```
网关 ESP32-S3
├── UART0  USART (GPIO15 TX / GPIO16 RX) → MAX3485 → 9600 Modbus 总线
│           MPPT 0x10 + 继电器 1/2/3/5 —— 现有，时序敏感，不动
└── UART1  (GPIO4 RX / GPIO5 TX 未接) ← MAX3485 ← TF03K 库仑计 19200 主动上报
            只接收，DE/RE 固定接地
```

### 接线表（RS485 版）

| TF03K | MAX3485 | ESP32-S3 | 说明 |
|-------|---------|----------|------|
| A | A | — | 差分正 |
| B | B | — | 差分负 |
| — | VCC | 3.3V | ⚠ 不是 5V |
| — | GND | GND | 共地 |
| — | **RO** | **GPIO4 (RX)** | 唯一必须接的信号线 |
| — | **RE + DE** | **GND** | 常接收。⚠ **不要**接 GPIO 做收发切换 |

> **GPIO5 (TX) 不用接**：TF03K 的 RXD 无接收功能，发过去没有意义。
> 配置里写 `tx_pin` 只是 `uart` 组件的必填项，**悬空即可**。

### 若实物是 TTL 版

不需要 MAX3485，直连即可：

```
TF03K TXD ── GPIO4
TF03K GND ── GND     （必须共地）
```

### ⚠ 终端电阻

TF03K **内部已含 120Ω**。这条线只有库仑计 + 网关两个节点时，两端各一 120Ω 才正确；
若网关侧 MAX3485 板上也焊了 120Ω，会导致**过量匹配**。接好后用万用表量 A/B：
约 120Ω = 正常（只库仑计一颗），约 60Ω = 两颗并联，需拆掉网关侧那颗。

> 待确认：实物是 RS485 版还是 TTL 版（决定是否需要额外一颗 MAX3485）。

## 五、实体规划（ESPHome sensor）

| 实体 id | 名称 | 来源字节 | 设备类 | 单位 | 说明 |
|---------|------|----------|--------|------|------|
| `coulomb_soc` | 库仑计-电量百分比 | 2 | — | % | 直接取，不换算 |
| `coulomb_voltage` | 库仑计-电池电压 | 3-4 | voltage | V | ÷100 |
| `coulomb_capacity` | 库仑计-剩余容量 | 5-8 | — | Ah | ÷1000 |
| `coulomb_current` | 库仑计-电流 | 9-12 | current | A | ÷1000，注意符号 |
| `coulomb_remain_time` | 库仑计-剩余时间 | 13-15 | duration | s | 秒，UI 转 hh:mm |

**未在帧内、需 ESP32 侧自算的量**（如"本次充入/放出 Wh"）：
协议**不含累计电量**，只有当前容量 + 剩余时间。若屏/HA 需要 `total_increasing` 电量，
需在 ESPHome 里对 `coulomb_voltage × coulomb_current` 做时间积分累计（类似 `integration` 传感器），并处理掉电归零。

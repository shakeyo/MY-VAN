> **目的**：把智能化剩余的活儿一次排完，按顺序做，每步有**入口条件 / 动作 / 验收**。
> 本文只讲**执行顺序与判据**，细节不重复——指向对应文档。
>
> **本计划基于的当前实物状态（2026-09）**：
>
> | 部件 | 状态 |
> |------|------|
> | 中8 模块（地址 2） | ✅ 已接负载 + DI，已在 38400 下实测通过 |
> | 中4 模块（地址 3） | ✅ 已接线，**保险未插（未通电）** |
> | 16DO 模块（地址 5） | ✅ **已到货**，地址已改 5、通道映射已验 |
> | 额头 8 路模块（地址 1） | ✅ **已到货**，待装 |

> **三条红线**：
> 1. 动功率线前先断电（拔保险或分总开关），确认后再动手。

> 3. 485 模块 12V 供电**正负严禁接反**（模块无保护，接反即烧）。

## 一、总览：执行顺序与依赖

```
第0步 通电前复查（无电作业）
   │
第1步 装额头模块 + 中4 通电 ─────┐
   │                              │
第2步 烧 test-channel-mapping ────┤ 全部通道/按键只读核对
   │                              │
第3步 烧 prod.yaml 全功能验证 ────┘
   │
第4步 全车 38400 → 9600 改造（MPPT 上车前必做）
   │
第5步 装 MPPT + 桌面实测定档
   │
第6步 烧含 MPPT 的 prod，能源联调
```

> **为什么 9600 改造必须排在 MPPT 之前**：MPPT 只支持 9600，继电器模块和固件现在都是
> 38400。两者挂同一条总线会**互相乱码、整条总线都用不了**（不是"MPPT 不工作"）。
> 详见 [4.7 改造](gateway/build-guide.md)。

## 第 0 步：通电前复查（无电作业）

**入口**：无（任何时候可做）。

**为什么先做这一步**：额头模块和中4 都要通电，通电前把接线复查一遍，比通电后烧模块便宜得多。

**动作**：

1. **中4 模块就位核对**：485 A/B 接线、12V 供电极性（**正负务必确认，接反即烧**）、GND 共地
2. **额头模块安装**：装进额头柜 → 485 并入总线（**菊花链，不可分支**）→ 12V 供电 → 核对极性
3. **驾驶室面板 6 键**接线到额头模块 DI（同柜直连，不设接头）：
   - 键1 射灯 → DI1 / 键2 倒车灯 → DI2 / 键3 DSP → DI3 / 键4 换气风扇 → DI4
   - 键5 预留 → DI5 / 键6 灯光模式 → DI6
   - **COM 必须接电源一极**（悬空则永不触发）
4. **总线上电前万用表检查**：A-B 间电阻（应约 2×120Ω ≈ 240Ω 量级，无穷大 = 终端电阻没接或断线）
5. **16DO 模块 LED 接线核对**：LED 阳极 → +12V；LED 阴极 → 电阻 → 16DO 对应 Y 的 COM；Y 的 NO → 模块 GND

**验收**：
- [ ] 三个模块（额头/中4/16DO）12V 极性全部确认无误
- [ ] 485 菊花链无分支，终端电阻仅 ESP32 端 + 当前最末端（16DO）
- [ ] 驾驶室 6 键 COM 已接电源一极
- [ ] A-B 间电阻为 240Ω 量级

## 第 2 步：全通道映射验证（只读固件）

**入口**：第 1 步完成。

**烧录**：

```bash
cd modules/10-smart-control/gateway/esphome
esphome run test-channel-mapping.yaml
```

**为什么用只读固件**：先确认"哪个键对应哪一路、哪颗灯对应哪个 Y"全对，再上生产逻辑。否则映射错了会误动真实负载。

**动作与判据**：

1. **web 点开关**（手机连 my-van AP → 192.168.4.1）逐个点，听继电器咔哒 + 看状态回读：

| 模块 | 通道 | 应动作 |
|------|------|--------|
| 额头（1） | R1/R2/R3/R4 | 射灯 / 户外灯 / DSP / 副驾排气扇 |
| 中8（2） | Y1-Y7 | 主灯 / 氛围灯 / 后窗扇 / 上水泵 / 电控水阀 / 冰箱 / 倒车灯 |
| 中4（3） | Y1-Y4 | 全空（未来负载），点了无反应 = 正常 |
| 16DO（5） | Y1-Y10 | 逐个点亮，对照面板 LED 位置 |

2. **按物理按键**逐个按，日志出现 `key: <名称>` = 该键 DI 映射正确
   - ⚠ **重点看中4 的日志**：`keys addr=03 n=?` —— `n` 是位图字节数（1 或 2）。这是唯一没法静态确认的点，**记下实测值**
3. **断电重启**：重新上电后全部开关应为关、LED 全灭

**验收**：
- [ ] 额头 4 路 + 中8 7 路 + 16DO 10 路 LED，web 点一轮全部对应
- [ ] 全部物理按键（10 颗）日志名称正确
- [ ] **中4 的 `n` 值已记录**
- [ ] 断电重启后全部为关

## 第 4 步：全车 38400 → 9600 改造（MPPT 上车前必做）

**入口**：第 3 步完成（38400 下功能已全部验证，排除变量）。

**操作步骤**（帧已备好，见 [gateway/build-guide.md §4.7](gateway/build-guide.md)）：

1. 主端（USB-485 或 ESP32）保持 **38400**，对目标模块发「写 9600」帧：
   | 模块 | 地址 | 帧 |
   |------|------|-----|
   | 额头 | 1 | `01 06 00 33 00 01 B8 05` |
   | 中8 | 2 | `02 06 00 33 00 01 B8 36` |
   | 中4 | 3 | `03 06 00 33 00 01 B9 E7` |
   | 16DO | 5 | 见下方补帧 ⚠ |
2. **立即切到 9600**，发「读回」帧，回 `XX 03 02 00 01` = 该模块已是 9600 ✅
3. 逐台重复（**逐台改、逐台验，不要一次全改**）
4. 4 台全改完后改固件（**共 4 处，一处不漏**）：
   - `base.yaml`、`test-485-connect.yaml`、`test-channel-mapping.yaml`、`test-mid8-logic.yaml`
   - `baud_rate: 38400` → `9600`
5. 重烧 `prod.yaml`
6. 快速复验第 3 步一轮，确认 9600 下无回归

> ⚠ **16DO 的 9600 帧需现场确认**：模块型号可能与继电器模块系列不同，寄存器地址未必同为 0033H。
> **稳妥做法：用厂家 PC 软件改**（带界面、可读回），不要盲发帧。
> 若确认同系列，帧为 `05 06 00 33 00 01 <CRC>` —— 需要时我按 CRC 算给你。

**出口验收**：
- [ ] 4 个模块在 9600 下读回 `00 01`
- [ ] `prod.yaml` 已切 9600 重烧，第 3 步复验通过
- [ ] **总线空闲无 0x00 噪声流**（有则查偏置/接地）

## 第 5 步：MPPT 接入 + 桌面实测定档

**入口**：第 4 步完成（全车已 9600）。

**5.1 物理接线**（[04-power-system](../04-power-system/) 侧）：
- MPPT DC 输出 → 空气开关 → 汇流排 → 电池
- 485 A/B 并上总线（**菊花链，不得分支**）
- 屏蔽层单端接地；总线与功率线间距 ≥15cm

**5.2 LCD 设置**（三处，务必确认）：
| 项 | 值 | 注意 |
|----|-----|------|
| 地址 | 0x10 | 固件按 0x10 写死 |
| 波特率 | 9600 | ⚠ **MPPT 的 9600 = 代码 4**（继电器模块是代码 1，勿混） |
| DC 输出控制方式 | 远程控制 | 写入 `0xD0/0x0C` 数据4=4，掉电保存 |

**5.3 桌面实测定档**（核心目的，9 项清单见 [mppt-protocol.md §6.1](../energy/mppt-protocol.md)）：

**第 6-8 项决定档位，是本次实测的关键**：

| 测什么 | 判据 |
|--------|------|
| 关 DC 输出后待机电流 | 归零 → **协议档**；不归零 → **硬件档** |
| 关输出后 485 是否响应 | 不响应 = 控制器整体掉电，协议档成立 |
| 断电恢复后能否自启并保持远程模式 | 能 → 协议档闭环 |

**验收**：
- [ ] MPPT LCD 三处设置确认无误
- [ ] 实测 9 项通过，**档位已定**（协议档 / 硬件档）
- [ ] 若定硬件档：加 63A/48V 直流接触器，线圈由**额头.R6** 驱动（触点带线圈 + 续流二极管）

## 第 6 步：能源联调

**入口**：第 5 步完成。

1. 烧含 MPPT 的 `prod.yaml`（`mppt.yaml` 已挂载）
2. **核对读数**：HA 里的 PV 电压 / 电池电压 / 充电电流 / 发电功率 / 总电量，**与 MPPT LCD 对照一致**
3. **时钟同步**：SNTP 校时后自动发 `0xDF`；确认 LCD 时间跟随（日发电量 0 点清零依赖它）
4. **离线检测**：拔掉 MPPT 的 485 → 实体应变为无数据
5. ⚠ **待位自动化尚未实现**：待机断电/恢复充电/低温禁充三条依赖档位，定档后我再补进 `mppt.yaml`

**验收**：
- [ ] 5 个关键读数与 LCD 一致
- [ ] 时钟同步生效
- [ ] 离线检测生效
- [ ] （定档后补）待机断电自动化工作正常
